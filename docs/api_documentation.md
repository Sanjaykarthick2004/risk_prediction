# API Documentation

Base URL: `http://localhost:8000/api`. Interactive docs (Swagger UI) are auto-generated by
FastAPI at `http://localhost:8000/docs` when the backend is running.

All endpoints except `/health` and everything under `/auth/*` require
`Authorization: Bearer <token>` (obtained from `/auth/login`).

## Auth
Username + password only — there is no email field or email verification in this project.

| Method | Path | Description |
|---|---|---|
| POST | `/auth/register` | Create a user (`username`, `password`, `role`: ADMIN/RESEARCHER) |
| POST | `/auth/login` | Form-encoded `username`+`password` → `{access_token, token_type}` |
| GET | `/auth/me` | Current user's profile |
| POST | `/auth/forgot-password` | `{username}` → issues a password-reset token. Always returns 200 with the same generic message, whether or not the username exists, to avoid leaking account existence. |
| POST | `/auth/reset-password` | `{token, new_password}` → sets the new password. Token is single-use and expires after `RESET_TOKEN_EXPIRE_MINUTES` (default 30min). |

**No real email/SMS is sent.** There's no mail provider configured for this project, so the
reset link is logged to `backend/logs/app.log` and returned directly in the API response
(`dev_link`) — a deliberate, clearly-labeled college-project shortcut. The frontend surfaces
this link directly in the "Forgot password?" form on the login page.

| Method | Path | Description |
|---|---|---|
| GET | `/athletes/{athlete_id}/assessments` | List an athlete's assessments |
| POST | `/athletes/{athlete_id}/assessments` | Create assessment (nested modality objects; demographic is auto-snapshotted from the athlete) |

## Dataset
| Method | Path | Description |
|---|---|---|
| POST | `/datasets/upload` | Upload CSV/Excel (multipart `file`) |
| GET | `/datasets` | List uploaded datasets |
| POST | `/datasets/{dataset_id}/validate` | Run validation, return errors/warnings/stats |
| POST | `/datasets/{dataset_id}/process` | Clean + engineer features, save `processed_data.csv` |
| POST | `/datasets/{dataset_id}/select-for-training` | Use this processed dataset the next time training runs |
| GET | `/datasets/training-selection` | Which dataset will be used next time training runs (synthetic default, or an uploaded one) |
| POST | `/datasets/reset-training-selection` | Revert to the bundled SYNTHETIC DEMONSTRATION DATA |
| GET | `/datasets/active-summary` | Viva-ready overview of the active dataset: population, actual record/feature counts, missing values, duplicates, class distribution — computed live |

## Training
| Method | Path | Description |
|---|---|---|
| POST | `/training/train` | Train & compare 6 baseline models on the active dataset |
| POST | `/training/xgboost` | Train default XGBoost only (fast, `n_search_iter=1`) |
| POST | `/training/optimize?n_iter=30` | Full pipeline: default vs. RandomizedSearchCV-optimized XGBoost, persists all model artifacts |
| POST | `/training/ablation` | Modality-ablation experiment (M1..M6) on the active dataset |
| GET | `/training/status` | Last training action + whether model artifacts exist |
| POST | `/training/auto-select-best-dataset?n_iter=30` | Quickly compares every trainable dataset by accuracy, then fully trains on whichever scores best |

## Predictions
| Method | Path | Description |
|---|---|---|
| POST | `/predictions` | Run a real-time prediction for one athlete's assessment, store it + its SHAP explanation |
| GET | `/predictions?athlete_id=` | List predictions (optionally filtered) |
| GET | `/predictions/{prediction_id}` | Get one prediction |
| GET | `/athletes/{athlete_id}/predictions` | Prediction history for one athlete |

### Example request — `POST /predictions`
```json
{
  "athlete_id": "ATH-001",
  "assessment_id": "ASM-xxxxxxxxxxxx",
  "training": { "training_hours_per_week": 9, "training_frequency": 6, "training_intensity": 8,
                 "weekly_distance_km": 55, "long_run_distance_km": 18, "speed_work_sessions": 2,
                 "training_load": 850, "acute_training_load": 900, "chronic_training_load": 700 },
  "physiological": { "resting_heart_rate": 72, "heart_rate_variability": 45, "fatigue_score": 8,
                      "muscle_soreness": 7, "recovery_score": 40 },
  "recovery": { "sleep_hours": 5.5, "sleep_quality": 5, "recovery_days": 1, "rest_days": 1 },
  "lifestyle": { "stress_level": 7, "hydration_score": 60, "nutrition_score": 65 },
  "injury_history": { "previous_injury": 1, "injury_count": 2, "previous_injury_type": "Runner's Knee",
                       "days_since_previous_injury": 90, "previous_recovery_duration": 45 }
}
```
The example values above are illustrative only — the returned `probability`, `risk_level`, and
SHAP factors are always generated live by the trained model, never hard-coded.
