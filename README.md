# risk_Injury_prediction

# Explainable Multimodal AI-Based Athlete Injury Risk Prediction Using XGBoost and SHAP

A full-stack college/final-year academic project: React + FastAPI + MongoDB, with an
XGBoost injury-risk model explained by SHAP.

> **Disclaimer**: This application is an academic research prototype for sports injury-risk
> prediction. Predictions are generated using machine-learning models and should not be
> interpreted as medical diagnoses, clinical decisions, or treatment recommendations. The
> system has not been clinically validated.

## Overview
The system integrates six categories of athlete information (demographic, training,
physiological, recovery, lifestyle, injury history) into one feature vector, predicts
short-term injury-risk probability with XGBoost, classifies it into LOW/MEDIUM/HIGH, and
explains every prediction with SHAP — both globally (which features matter overall) and
locally (why this athlete, right now). The current research population is **running
athletes** (Sprint / Middle Distance / Long Distance / Cross Country / General Running) —
see [docs/project_overview.md](docs/project_overview.md) for why a single-sport population
was chosen.

See [docs/project_overview.md](docs/project_overview.md) for the full problem statement,
objectives, research questions, and hypotheses.

## Dataset
No real clinically-validated injury dataset is bundled. The backend auto-generates a
**SYNTHETIC DEMONSTRATION DATA** set of running athletes (`app/ml/data_loader.py`) the first
time training runs — 10,000 records by default (configurable via
`settings.synthetic_dataset_size`), reproducible with a fixed seed — so the whole pipeline can
be exercised without a real dataset. Upload your own CSV/Excel via the Dataset page to use real
data instead — see [docs/methodology.md](docs/methodology.md) for the required columns, the
generation method, and the target-leakage precautions taken.

## Feature Description
Engineered features (BMI, workload ratio, sleep deficit, recovery gap, stress-fatigue index,
injury-history score, training-recovery balance) are documented with formulas and rationale in
[docs/methodology.md](docs/methodology.md).

## Installation

### Prerequisites
- Python 3.10+
- Node.js 18+
- MongoDB Community Server running locally (`mongodb://localhost:27017`)

### MongoDB Setup
Install MongoDB Community Server and make sure its service is running. No manual database
creation is needed — the app creates the `explainable_injury_ai` database and its collections
automatically on first write.

### Backend Setup
```bash
cd backend
python -m venv venv
venv\Scripts\activate
pip install -r requirements.txt
copy .env.example .env
python run.py
```
Runs at `http://localhost:8000` (Swagger docs at `/docs`).

### Frontend Setup
```bash
cd frontend
npm install
copy .env.example .env
npm run dev
```
Runs at `http://localhost:5173`.

## How to Run
See [docs/user_manual.md](docs/user_manual.md) for the full walkthrough: register → login →
train the model → add an athlete → run a prediction → explore SHAP → view evaluation →
generate a report.

## Model Training
`POST /api/training/train` (baseline comparison), `POST /api/training/optimize` (default vs.
hyperparameter-optimized XGBoost — this is the one that persists the model used for
prediction), `POST /api/training/ablation` (modality ablation). Also triggerable from the
**Model Training** page in the UI. Actual metrics are always generated by training, never
hard-coded — see [docs/experiments.md](docs/experiments.md) for a real run's results.

## Prediction
Once a model has been trained, use the **Prediction** page (or `POST /api/predictions`) to
submit an athlete assessment and get a live probability, risk level, and SHAP explanation.

## SHAP / Explainability
`shap.TreeExplainer` on the persisted XGBoost model. Global importance, local waterfall
breakdowns, and feature-dependence plots are all available via the **Explainability** page /
`/api/explainability/*` endpoints. See [docs/methodology.md](docs/methodology.md) for how SHAP
values should (and should not) be interpreted.

## Experiments
Four research experiments are implemented and reproducible from the UI or API — model
comparison, XGBoost optimization, modality ablation, and global/local SHAP analysis. See
[docs/experiments.md](docs/experiments.md) for one actual run's results.

## Limitations
- Bundled data is synthetic; real-world validation would require a licensed dataset with
  genuine future injury outcomes.
- Single train/test split per experiment (no repeated k-fold reporting across seeds).
- Training runs synchronously in the request (fine for this dataset size; would need a task
  queue for a much larger dataset).
- Risk thresholds (LOW/MEDIUM/HIGH) are configurable demonstration thresholds, not clinically
  validated cut-points.
